# Fallback/native coexistence

The blocking condition was WAM's cold image-name exclusion, not an observed dyld collision. `otool -hv/-L` shows TWOLEVEL native images and the native codec importing `libavutil-wamnative.61.dylib`. The retained real mpv closure imports unsuffixed FFmpeg images. `symbol-probe.txt` records distinct function addresses and image owners, with simultaneously independent `av_log` levels 17 (fallback) and 29 (native). No shared `av_log` state was observed; an av_lockmgr explanation was not assumed.

Both blanket exclusions are removed. The cold loaders still serialize on their shared mutex, native function tables use `RTLD_NOW | RTLD_LOCAL | RTLD_FIRST`, native ABI/license/configuration checks remain, and mpv's descriptor/image-identity checks and process-lifetime runtime cache remain. No API objects cross the two FFmpeg closures.

The existing coexistence test now verifies both load orders, native symbol ownership, independent leases and final native retirement while the fallback stays cached. Restoring either original loader independently fails that test; both sources are restored byte-identically (`coexistence-revert-proof.json`, 0/1/0 twice).

Real GUI proof uses only the build app, opt-in codec ON, an ASF/WMAv2 fallback followed by native software MPEG-4 ASP, in one process. Both windows play; native frames increase after closing the fallback window. `coexist-fallback-first-final` retains the stream, diagnostics and vmmap inventories at 4/7 seconds showing both cached mpv and native codec images. `coexist-native-first-final` proves the reverse order and preservation of the existing native session. No closure refusal occurs. The fallback-first native stream increases from 43 to 142 drawn frames; the native-first stream increases from 45 to 184. These short coexistence trials include vmmap observations and are not resource or all-drawn benchmarks. The initial broken development seed (missing Homebrew codec 62) was not counted as a coexistence pass; the local retained phase-2e packaged fallback closure supplied the measured build-bundle dependencies. No installed app was changed.

Cost: the successful fallback closure is still cached for process lifetime, and simultaneous routes retain both distinct FFmpeg closures. The prior process-lifetime native admission ban is removed; no resident-memory equivalence to a single closure is claimed. Packaging remains lazy, with no eager native codec load command.
